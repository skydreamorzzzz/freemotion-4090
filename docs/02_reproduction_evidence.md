## 随机初始化如何做到可解释

使用上游构造函数，固定 seed=20261003。不任意指定一个“看起来合理”的正态分布覆盖全部参数。保留网络输出层和交互连接层的零初始化；CLIP 使用本机缓存的官方预训练参数。单人和多人 checkpoint 均保存于 synthetic optimizer step 之前，包含版本、配置、随机种子等元数据；JSON 报告另外记录 checkpoint SHA256 和归一化统计文件 SHA256。

多人的主干和控制分支通过上游 `load_state_dict` 的阶段迁移逻辑从随机单人权重复制。保存的完整 checkpoint 严格重载则调用基类 `torch.nn.Module.load_state_dict`：上游 override 会把主干键再次映射到控制分支，它是阶段迁移逻辑，不应不加区分地拿来重载已训练的完整交互状态。是否影响官方评价需要进一步核查具体 state_dict 顺序。

## 已测结果

GPU：RTX 5060 Laptop 8 GB；Python 3.12.10；torch 2.11.0+cu128；numpy 2.4.2。原尺寸模型，batch=1、16 帧。

| 检查 | single | multi |
|---|---:|---:|
| 参数数 | 288,648,710 | 451,604,236 |
| DDIM50 输出形状 | 1×16×1×262 | 1×16×2×262 |
| 输出有限 | 是 | 是 |
| 归一化输出最大绝对值 | 0 | 0 |
| 非零梯度张量数 | 2 | 0 |
| 完整 checkpoint 严格重载 | 通过 | 通过 |

原始输出层为零初始化，所以初始预测为归一化空间零，反归一化后对应均值特征；它不是有意义的人体动画。单人第一次反向只有输出层获得非零梯度，完成一次 AdamW 更新且参数有限。更新后的参数未保存为随机 checkpoint。

多人从随机单人模型出发并冻结主干时，冻结的零输出层使输入特征的梯度为零；本次实测非零梯度张量数为 0。结论：不能跳过单人学习阶段直接用随机冻结主干训练交互分支。不要为了让梯度“好看”改掉官方零初始化。

两次初始合成数据验证的几何损失均为零，不能据此判断低时间步几何项是否正确；随后追加真实样本和固定 `t=500` 的检查，几何项及反向传播均通过（详见下文）。初始合成数据损失不属于 baseline 训练结果或论文指标。

## 真实样本与原训练入口验证

`artifacts/real_data_smoke.json` 记录了 3 次真实样本更新。沿用原始数据类、坐标处理、镜像增强、300 帧 padding、原始扩散损失与 AdamW；本次将 batch 设为 1、workers 设为 0、CACHE=False。学习率因原始 warmup 从 `1e-5` 起步，并非遗漏了配置中的 `1e-4`。

| 更新 | 样本 | 有效帧数 | total loss | 非零梯度张量 |
|---|---|---:|---:|---:|
| 1 | 2165_swap | 109 | 0.705611 | 2 |
| 2 | 7310_swap | 161 | 7.669107 | 116 |
| 3 | 4468_swap | 40 | 6.515639 | 154 |

三个样本、文本和随机时间步不同，不能用这些 loss 的大小变化判断收敛。它们证明真实数据能经过预处理、文本编码、扩散损失和参数更新。后续固定 `t=500` 的检查得到 VEL_A=3.345328、BL_A=0.009728、FC_A=0.000213，总 loss=9.848463，梯度全部有限。

原始 `tools/train.py` 也通过了单卡 Lightning 的 3 次更新，日志明确显示 `Trainer.fit stopped: max_steps=3 reached`，退出码 0；三个 total loss 与独立检查一致到日志精度。证据保存在 `artifacts/lightning_train_smoke.log`。没有完成一个 epoch，更没有完成单人 2500 epoch、交互 1000 epoch；不据此声称得到有效的训练后 baseline。

随机 checkpoint 始终是更新前状态。独立真实数据 smoke 不保存更新后的权重，避免混淆初始化和训练产物。

## 兼容性与未完成事项

1. 本机已有 Python 3.8/torch 1.13.1 环境，但缺少模型依赖；本次使用可在当前 GPU 执行的新版环境。尚未声称与原环境数值等价。
2. 实测上游 CosineWarmupScheduler 在当前 torch 报 `unexpected keyword argument 'verbose'`。仅加构造函数参数兼容分支，余弦与 warmup 公式保留。
3. 上游训练入口默认 DDP/NCCL。本次 Windows 分支改为单 GPU 的 auto strategy，其他平台保留 DDP；添加可选 seed 和 max_steps 用于可重复的有界验证。入口 `--help` 已通过；完整训练验证另见实测记录。
4. 尚未完成真实两阶段训练、正式评价及论文数字复现。数据下载和验证状态单独记录，不用随机生成物补表格。
5. 官方 InterCLIP checkpoint 含旧 NumPy scalar 元数据，torch 新版默认 weights_only 加载报错。本次仅允许该文件所需的 NumPy scalar/dtype 类型，不关闭 weights_only。严格参数加载通过，合成文本/动作输入均得到有限的 512 维嵌入；不是评价分数。
6. SciPy 1.18 删除 `sqrtm(..., disp=False)` 接口。对函数签名做兼容分支，保持 FID 公式；已验证零均值、协方差 I/2I 时 FID 为 `6-4*sqrt(2)`，以及均值差 [1,1]、协方差相同时 FID=2。

## 数据下载来源

`downloads/interhuman_manifest.json` 是首次通过嵌入页面取得的**不完整目录快照**，标注和原始 pkl 各只返回前 5500 项。不能把它解释为官方数据总数。之后通过同一公开目录的分页 API 取得 `annots_full_manifest.json`：7897 个 Drive 文件、7838 个不同文件名，其中 7779 个纯数字 ID，另外 59 个带 `(1)` 的文件名。59 组同名不同 Drive ID 的文件逐份下载到 annotation_variants，并验证字节哈希相同，才合并到一个本地路径。

标注下载最终报告完整覆盖 7842 个目标路径（7838 个文本 + 3 个划分 + 许可证），失败数 0。首次并发下载曾因同名文件共享临时路径发生冲突，现已改为按路径分组和按源 ID 保存变体，最终检查通过。这属于数据获取问题，不是模型算法改进。

本次训练使用作者预处理动作压缩包，不下载原始 pkl 并重复 SMPL 处理。动作 ZIP 为 2,462,028,219 字节，CRC 检查通过；评价 checkpoint 为 1,513,626,777 字节，ZIP CRC 检查及模型严格加载通过。单人标注 ZIP 也通过 CRC 检查。最终覆盖率和完整性以 `artifacts/data_audit.json` 为准。

两份整体标注（4642、5834）含 GB18030 字节 A1 AF，对应右单引号 U+2019，而非 UTF-8；原文件保持不变。审计显式记录了 GB18030 解码回退。上游 dataset 使用系统默认编码，本次 Windows 默认编码可读取；迁移到 UTF-8 默认的系统时需要明确处理这两份文件，不能删除乱码或悄悄改文本。

## 最终数据覆盖与不能声称的等价性

原始 split 共 7779 个不同 ID，train/val/test 两两无交集。预处理动作每个人各 7777 条，缺 3945、4106；个人描述每个人各 7770 条，其中以下 9 条虽有动作却缺个人描述：4193、4385、4434、6028、6940、7220、7221、7543、7561。

本次使用上游支持的 `ignore_list.txt` 显式排除这 11 个 ID，来源标记为“本次新生成的缺失资产排除”，并未声称它是作者原来的过滤规则，也未补写不存在的个人描述。官方三个 split 文本不变，SHA256 记录在审计 JSON。

| 划分 | 官方名单 | 动作和三类文本齐全 | 再按原始长度阈值过滤 |
|---|---:|---:|---:|
| train | 6022 | 6013 | 5629 |
| val | 580 | 579 | 546 |
| test | 1177 | 1176 | 1099 |

完整配对的 7768 条中，494 条短于原代码的 15 帧阈值，因此被原始 `load_motion` 过滤；它们不是新增的人工排除。其余资产审计未发现非有限动作值、人物帧数不一致或三类文本行数不一致。行数一致并不证明语义对应无误，仍需后续样例检查。

这组可用样本数量尚未与作者实际实验清单核对；归一化统计沿用官方仓库文件，其生成是否严格只使用训练集也未重新验证。当前不能声称数据协议与论文实验完全等价。
