# 从 DPMotion 提炼矫正候选（本次代码审阅）

用户明确授权阅读旧 DPMotion 的思想。这里只记录静态代码核查和新候选，没有复制旧实现、运行其模型或将其结果算作 FreeMotion baseline；不能据此声称恢复了当年的设计动机。

## 实际机制

旧目录 `DPMotion/DPMotion.py` 的生成入口把组关系和距离权重交给 `models/nets.py:forward_single`，实际走 `p_sample_loop_multi` → `p_sample_with_grad` → `gradients` → `compute_group_person_losses`。在预测干净动作反归一化后，以米为单位计算 XZ 平面的距离违规损失，再经去噪器反传到当前带噪动作，修正采样。组中心距离与跨组成员距离共同参与，适用于互不相关群体的隔离；组内距离在该入口置为 None。

这是一种“把可描述的几何错误写成损失，在采样时矫正”的思想，不是重新训练生成器。根节点距离不能保证肢体没有穿透；拉开所有人也会破坏拥抱、握手等必要接触。因此必须区分交互关系，不能统一套最小间距。

RAG 实际检索 CLIP 编码的文字标注，将相似案例提供给 LLM 生成场景配置；并没有把检索动作直接融合进扩散特征。它可能帮助动作描述明确，但不能替代模型学会骨架与运动。

## 不能照搬的细节

- 顶层 `compute_non_interactive_loss` / `compute_orientation_loss` 在所查 Python 调用中只有定义；默认生成走上述另一条损失路径。入口 angle_weight=0，生成的 orientation 没有经 `_build_inter_graph` 写入约束，不能声称默认朝向矫正已生效。
- 共享梯度函数还包含满足条件时的 GLI topology loss，并非严格只有距离约束。要做“距离引导”对照，需明确隔离其他损失。
- 引导含 `1000/(t+100)` 和外层 `5+5t/1000` 两重缩放。距离部分的合成倍率总体在后期增大，与部分“后期减弱”注释不一致；实际梯度大小还取决于去噪器与损失。不能直接将 DDPM 1000 步参数套到 FreeMotion DDIM50。
- 旧入口在导出的关节坐标上做时间高斯平滑，但 feat262 单独保存为未平滑版本。可视化与指标输入需明确一致，平滑不代表生成质量自然提升。
- 知识库构建遍历给定 annots 目录，没有内部 train split 筛选。旧 pickle 是否混入测试标注未经核查；新的检索实验应按 train ID 重建，不能直接复用。
- 旧生成入口依赖 InterGen checkpoint，不能将其自然动作能力归功于距离矫正或 RAG。

## 适合当前问题的候选顺序

| 候选 | 想解决的问题 | 如何判断有效 | 状态 |
|---|---|---|---|
| 骨长一致性与地面约束的轻量投影 | 当前单人骨架压缩、脚穿地 | 骨长时间波动、穿地深度、脚滑及动作幅度同时检查 | 本次提出，尚未实现；不是旧 DPMotion 已有成果 |
| 将同样约束放到采样后段，修正预测干净动作 | 比最终后处理更早约束几何错误 | 与无矫正、仅后处理作同 seed 对照，记录引导前后损失和显存 | 本次提出，尚未实现 |
| 非交互人群的距离区间引导 | 群体挤在一起、错误接近 | 违规率、碰撞与交互保持程度，不只看 FID | 来自旧实现思想；当前单人问题不优先 |
| train-only 文本检索辅助描述 | 文本模糊或多人分工混乱 | 原描述 / 改写 / 检索改写逐项比较语义指标 | 来自旧实现思想；欠训练生成器仍是限制 |

优先做几何错误的量化，再在固定 val 案例上比较“无矫正 / 轻量后处理 / 采样中矫正”。所有阈值与骨长先验只能来自 train，不能用目标 val/test 动作当引导。单纯压低速度或把人拉开可能让几何指标好看却破坏动作，必须同时展示运动量和原始未平滑结果。若只修改位置特征，还需确保速度和旋转等 262 维表示的一致性，不能把不一致特征直接送进评价器。

这些候选解决几何错误，不足以解释或修复当前 FID 161.678 与低文本命中率。baseline 训练和冻结文本适配层的核查仍需独立进行；矫正实验不得混入 baseline 指标。
